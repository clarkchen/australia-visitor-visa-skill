# 澳洲 600 访客签证材料助手

本项目默认使用简体中文编写说明文档；`README.md` 为中文入口。英文仅用于申请文书模板、代码标识及必要的官方名称。

面向境外成年申请人的通用 Codex 技能：以纯旅游为默认入口，支持单人、夫妻及家庭同行，并提供参会访问和陪同旅游流程。家庭含未成年人时须另行核实其专项要求，不直接套用成人模板。

| 场景 | 整理重点 |
|---|---|
| 纯旅游（默认） | 旅游计划、资金、实际工作或其他身份、回国安排 |
| 参会访问 | 在共用材料上增加会议活动及证明、适用的派遣和费用承担 |
| 陪同旅游 | 在旅游材料上增加真实同行关系、参会背景和独立旅游安排 |

“主申请/副申请”仅在参会与陪同共同整理时作为材料称呼；纯旅游不分主副。每个人分别核实类别、整理材料和申请状态。仓库包含通用流程、空白模板和本地文件预检工具。

## 内容

入口：[`skills/australia-visitor-visa/SKILL.md`](skills/australia-visitor-visa/SKILL.md)

- `references/tourism.md`：默认纯旅游流程，支持单人、夫妻及家庭同行。
- `references/main-applicant.md`：参会流程及适用的会议、派遣和工作证明。
- `references/accompanying-applicant.md`：陪同旅游流程，按实际关系补充参会背景。
- `references/case-study.md`：通用复盘框架，不记录真实申请结果。
- `references/person-document-linkage.md`：结婚证持证人/双方当事人、房产证权利人/共有人与申请人的三向对应检查。
- `references/evidence-workflow.md`：材料组织、流水与译件处理经验。
- `references/official-sources.md`：现行要求的官方核实入口。
- `references/scans-and-upload.md`：模型看图、本地文字识别（OCR）、扫描清晰度和附件大小/数量处理。
- `scripts/preflight.py`：只读检查字节数、PDF 页数、文字层、加密状态及图片像素，默认不联网、不调用 OCR。
- `assets/attachment-review.md`：原始扫描与最终上传版的独立检查记录。
- `assets/drafting-templates.md`：英文起草模板和上传清单结构。

## 安装与使用

将 `skills/australia-visitor-visa` 目录复制到 `~/.codex/skills/`（或你的 `$CODEX_HOME/skills/`），然后在新的会话调用：

> 使用 $australia-visitor-visa，按纯旅游检查我的材料，整理英文说明信、行程和上传清单。

也可指定“我独自参会”或“一人参会、一人陪同旅游”，只加载对应流程。

图像识别由宿主模型的看图能力或可用本地 OCR 执行；预检脚本只做机械检查，不自动判定清晰度和官方接受。脚本按文件类型使用 pypdf、Pillow，优先复用已有环境。

仓库只包含脱敏经验、模板和通用代码；原始材料、身份标识、财务数据和含个人信息的生成脚本均未收录。获签不代表所有历史做法都是普遍适用要求，实际申请需核实当前官方规定。

## 隐私与发布

本仓库仅包含通用流程、空白模板、文件预检工具和使用虚构文件的测试，不包含真实申请资料或原始案例提交历史。

真实证件、财务信息、填写后的文书、OCR内容及检查报告必须保存在仓库之外的私有目录，不上传到本仓库；.gitignore 不能代替内容审核。

预检脚本不调用网络或OCR服务；图像识别由宿主模型或用户选择的本地工具完成。新增外部处理应先说明服务和数据范围并获得授权，不能承诺宿主模型处理一定完全在本机进行。

发布更新时应复核文件内容、文件名、提交作者及提交历史，避免把个人资料或私人邮箱写入版本库。
