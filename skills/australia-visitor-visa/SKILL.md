# 澳洲 600 访客签证材料助手

目标是产出真实、可追溯、相互一致的申请包。仓库只保留通用流程、空白模板和通用代码；个人材料与申请结果保存在仓库之外。

## 按实际活动选择场景

先从用户描述和已有材料判断每位申请人的实际目的，不从婚姻关系或同行关系推断类别。未出现参会目的且明确为观光度假时，以纯旅游流程为默认入口；目的尚不清楚时先确认，不替用户假定。

- **纯旅游（默认）**：读取 [纯旅游流程](references/tourism.md)，支持单人、夫妻及家庭同行；逐人整理目的、行程、资金和回国安排，不要求会议或派遣证明。
- **参会访问**：读取 [参会流程](references/main-applicant.md)，在共用材料上增加实际会议活动、参会证明及费用承担，单位派遣只在适用时处理。
- **陪同旅游**：读取 [陪同流程](references/accompanying-applicant.md)，在旅游材料上增加真实同行关系、参会背景及独立旅游安排。

参会与陪同共同办理时，可用“主申请（参会者）/副申请（陪同者）”组织材料；它们不是附属签证身份，不代表自动获签或共用一份申请。纯旅游不划分主副，家庭中一人出资也不改变其他人的独立申请身份。

只处理一人时读取其对应场景；多人同行时分别建立事实表、说明信、清单和状态，按各自活动选择流程，再核对共同部分。每人可同时有参会及观光活动，应如实描述并核实类别，不因含观光就改成纯旅游。家庭含未成年人时，本 skill 可先整理成年人的材料，未成年人的同意书、监护和关系等专项要求须另行核实，不套用成人模板。

## 开始工作

先确认每位申请人申请时及拟决定时的所在地、年龄和实际活动，本流程聚焦境外成年申请；不适用者先核实对应官方流程，不套用成人境外模板。

处理图片、扫描件或准备最终附件时，先读取 [图像与上传检查](references/scans-and-upload.md)，使用本地预检脚本辅助；清晰度必须回到原图及最终上传版目检。

先盘点用户已有文件，区分原件、译件、草稿、上传版、已提交记录和获签结果。不要仅凭文件名或旧 TODO 判断已经递交；无法确认的状态标为待核实。

建立每位申请人的事实表：护照姓名及姓/名、身份、实际访问目的、同行关系、出发/抵达/返程日期、住宿状态、工作与准假、费用承担、本人签证和拒签历史。优先从证据提取，只追问影响材料真实性的缺口。

使用前查阅 [官方入口](references/official-sources.md)，实时核实适用 stream、翻译、表格、上传限制、费用与程序要求。无法联网时说明哪些要求尚未核实，不把历史个案当成现行规定。会议参加者的类别应按其实际活动另行核实，不因为配偶是旅游就默认二人同一类别。

## 组织证据链

按 [材料与一致性检查](references/evidence-workflow.md) 整理。处理结婚证、房产证或其他涉及多人角色的证件时，必须读取 [证件人物对应](references/person-document-linkage.md)，区分持证人、双方当事人、权利人/共有人及上传者，并交叉核对原件、译件与说明信。解释信围绕访问目的、旅行计划、费用来源、工作及回国安排展开，每个关键说法指向材料；避免堆砌资产和无法佐证的承诺。

单人独立维护申请记录；多人同行仍逐人维护。旅游陪同者不能因配偶参会就自称注册参会者；费用承担按文件列明的对象和范围核实，不从一方获报销推断另一方获报销；如确实覆盖双方则如实说明。拒签史、旧签证、学历和资金分别归属对应本人。

中文原件和英文译件配对。译者信息按当前官方要求填写，资格和经验只写真实内容。默认提供所提交非英文材料的完整英文译件。工资节选或英文汇总仅作为阅读辅助，不替代要求的译件；仅在适用官方要求明确允许时采用节选，并记录依据、范围和源页码。

使用 [英文起草模板](assets/drafting-templates.md)，把所有方括号替换为本次已确认事实；未知内容留在待办清单，不补造。

## 输出和核验

个人材料必须输出到 skill Git 仓库之外的私有目录；先核对实际路径，不能因被 .gitignore 忽略就将真实材料放入仓库。私有目录按 `applicant-a/`、`applicant-b/` 等中性名称分人，单人不需建立第二人目录；每人内采用 `originals/`、`drafts/`、`upload-ready/`、`archive/` 分层。多人需要共同行程或关系证据时，可放在私有 `shared/` 中，分别上传所需副本；不覆盖原件。文件按证据主题命名，保持原件与译件可对应。PDF 检查页数、方向、裁切、可读性和关键字段，长表需目检分页；合并后重新打开验证。若保留银行高亮，使用副本且不遮盖数值和银行验真内容。

提供上传清单：文件名、所属申请人、证明事项、原件/译件关系、建议系统类别、缺口、确认状态。类别及大小、格式、数量限制以实际 ImmiAccount 页面和适用官方说明为准，记录来源；未知上限不得判定通过。最终合并或压缩后重新检查，不能以牺牲清晰度来满足体积。签字、日期、表格要求逐项核对，准备完成不等于提交完成。

核对表格、说明信、行程、在职准假、银行流水、适用的同行证据中的日期、姓名、单位和费用承担。航班搜索截图不能称为已出票，计划住宿不能称为已预订。

## 获签后

从通知逐项提取签证类别/stream、批准日、最晚入境日、每次停留长度、入境次数和全部条件。分清最晚入境日与每次停留长度，不把签证写成默认一年或默认可工作。条件原文优先；需要进一步解释时查官方条件页或 VEVO。

复盘时读取 [通用复盘框架](references/case-study.md)。只记录有证据的时间点和结果，不从文件修改日倒推递交日，不编造审理用时或免补件经历。

原始护照、银行、税务、地址、联系方式、签名及申请标识保存在用户私有材料目录；可分享 skill 只收录脱敏方法与空白模板，不复制含个人数据的历史生成脚本。

## 分享范围

用户要求不上传真实信息。上传前只取经过检查的当前通用文件，不能推送含旧案例细节的历史提交；发布时仅将经人工复核的通用说明、模板及已审查脚本白名单复制到全新目录并初始化 Git，不复制 .git、标签、旧分支或作者元数据，使用不含私人邮箱的发布身份，也不能上传私有原件、摘要或生成脚本。对真实信息的分享不从本 skill 的使用请求中推定授权。
