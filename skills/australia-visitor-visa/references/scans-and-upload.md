# 图像识别、扫描清晰度与上传限制

## 谁负责识别

Skill 是给宿主模型的指令，可以调用宿主的图像查看能力及本地工具，不要求每项能力都封装成自带代码。宿主若不能看图，也没有可用本地 OCR，应报告无法识别，不从文件名推测内容。

先使用 PDF 原有文字层定位内容；扫描 PDF 逐页渲染后查看，图片使用原尺寸或关键区域放大查看。可用本地 Tesseract 等 OCR 辅助查找和提取；先检查已安装的工具及语言包，不自动把证件发给外部 OCR API。宿主模型处理也可能经远端服务，不承诺整条链路纯本地；新增外部处理须先说明用途、服务和数据范围并获得授权。

OCR 文字只能作为提取候选，姓名、证件号、金额、日期及印章等关键字段要回原图复核。读不清时标记无法辨认并请求更清楚来源，不按上下文补全。识别成功不代表图像清晰，文字层也可能是错误的旧 OCR。

## 本地机械预检

运行 [preflight.py](../scripts/preflight.py)，PDF 需 pypdf，图片需 Pillow；优先使用宿主已有依赖。脚本只读文件，不转格式、不压缩、不调用网络。不能替代模型/人工目检，也不判断官方是否接受。

在 skill 根目录运行（把路径换成仓库外的私有文件）：

```bash
python scripts/preflight.py /path/to/private-case/document.pdf
```

已从当前上传页面确认最大字节数后，再提供 `--max-bytes`。参数表示包含边界的最大字节数；如页面规定严格小于 L，应传 L-1。MB 与 MiB 分别为 1,000,000 与 1,048,576 字节，页面只写 MB 且口径不明时先留裕量，不凭文件管理器四舍五入显示判断。不同类别上限不同就分批运行。

脚本报告包括实际字节数、相对指定上限的状态、PDF 页数/文字层/加密状态、图片像素/方向/DPI元数据。没有指定上限时明确标记待核实，不默认通过。返回码 0 仅表示未发现机械阻断，1 表示发现阻断，2 表示缺上限/依赖等检查未完成；即使返回 0，仍需目检和核对格式、附件数量。输出为中性文档编号，不含文件名、路径或提取正文；按输入顺序在私有清单里建立对应关系。

JSON 报告若需保存，只写入私有申请目录。脚本不会输出 OCR 正文，不能用它代替图像识别。

## 清晰度检查：原件与最终上传版都做

1. 保留下载原版、原始扫描和照片。先查来源质量，区分原扫描模糊与合并、压缩后的损失；有银行电子原版就优先使用，不先截图再转 PDF。
2. 扫描可从彩色、约 300 dpi 起步，这是实用建议而非移民局统一标准。小字、淡章或过密流水应调整采集条件并重扫；已有模糊图上采样或修改 DPI 标签不能恢复细节。
3. 逐页检查方向、四边完整、反光、阴影、手指遮挡、透页、印章/签字及正文。不能只看缩略图或首页。多帧图片检查全部帧，转换后核对页数。
4. 在原尺寸和必要放大下核对最小正文、金额小数点、日期、证件字符及验真信息。把“能看清”“OCR读出”“内容核对正确”分开记录；像素、DPI 或压缩率不能单独判定合格。
5. 对最终上传文件重新打开逐页核验；只检查输入原件不够。保存原版与最终版页数、大小、处理方法及目检状态。

## 附件大小与数量：先核实，再处理

查 [官方附件说明](https://immi.homeaffairs.gov.au/help-support/applying-online-or-on-paper/online/attach-documents-to-your-application) 和当前 ImmiAccount 上传栏，记录适用人/类别、格式、每文件大小上限、附件数量及剩余名额、核实时间和依据。动态页若未返回限制正文，应标为未核实，不能把旧攻略的 5MB、10MB 或数量照搬为现行要求。

预留合理大小裕量；最终合并、译者页、封面、签字页或高亮都可能改变大小，必须对最终上传文件重跑预检。小于上限、清晰可读、内容完整、类别/数量可接受是独立检查项，不能互相替代；本地通过也不等于系统已收件。

超限时按以下顺序处理：

- 优先从清晰原件重新导出，保留原生 PDF 文本和矢量；先尝试无损优化，不默认把所有页面栅格化。
- 图片类副本按小步调整分辨率/质量；每轮比较关键小字、数字和淡章。正文出现损失就停止降质，不为了压到上限而交模糊件。
- 仍超限且当前上传流程允许时，按页或自然章节分卷，核实剩余附件名额；用 Part 1 of N、原页码范围及私有清单维持完整性。不能删关键页，也不能把一张长页切开却漏掉连接关系。
- 若名额与大小无法同时满足且保持清晰完整，报告阻断并查官方替代途径，不暗中丢页、打包 ZIP 或上传到公开网盘。

更改可能影响电子签名；有电子签名时保留签名原版，不把重写或分卷后的副本称为签名仍有效。密码/加密、格式及上传错误分别核实，不因“本地能打开”推断系统会接受。

## 完成记录

使用 [附件检查表](../assets/attachment-review.md)。涉及多人角色的证件先完成 [人物对应](person-document-linkage.md)。状态分开记录：人物角色已对应、内容已复核、清晰度已目检、大小已检查、格式/数量已核实、系统上传成功。任何一项未知都不写成“可直接上传”。
